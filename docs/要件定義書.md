# tdb 要件定義書

## 1. 文書の目的

本書は、Rust + `ptrace(2)` で実装された Linux/x86_64 向け C プログラム用デバッガ
`tdb` について、実装済みの機能・制約に基づいて要件を整理したものである。
新規開発の企画書ではなく、既存実装(2026-07-27 時点、コミット
`472de27` 以降の状態)を正として作成した**現状追認型の要件定義書**である。
以降の変更は本書と [基本設計書](基本設計書.md)・[詳細処理手順書](詳細処理手順書.md)・
[テスト仕様書](テスト仕様書.md) を合わせて更新するものとする。

## 2. 対象読者

- tdb の機能追加・改修を行う開発者
- tdb を利用して C プログラムのデバッグを行うユーザー

## 3. 用語定義

| 用語 | 説明 |
| --- | --- |
| ptrace | Linux カーネルが提供するプロセストレース用システムコール。tdb の実行制御・レジスタ/メモリアクセスの基盤。 |
| PIE | Position Independent Executable。ロードアドレスが実行時に決まる ELF 実行ファイル。 |
| DWARF | ELF に埋め込まれるデバッグ情報形式。行番号・変数・型情報等を含む。 |
| ブレークポイント | 指定アドレスの命令を `int3` (`0xCC`) に置き換えて実行を停止させる仕組み。 |
| ウォッチポイント | x86-64 のデバッグレジスタ (DR0-DR7) を用いた、メモリ書き込み監視の仕組み。 |
| フォーカススレッド | `print`/`step`/`backtrace` 等、単一スレッドを対象とする操作の対象となる、現在選択中のスレッド。 |
| プロセスリーダー | `fork(2)`/`vfork(2)` により生成された、独立したアドレス空間を持つプロセス(スレッドと区別する単位)。 |
| リンク時アドレス | ELF ファイル上の(ロードバイアス加算前の)アドレス。 |
| 実行時アドレス | プロセス起動後、ロードバイアスを加算した実際のメモリアドレス。 |

## 4. システム概要

tdb は、GDB を参考にした対話コマンドライン(REPL)形式の C プログラム用
デバッガである。`ptrace(2)` を用いてデバッグ対象プロセスを直接制御し、
ELF シンボルテーブルと DWARF デバッグ情報を解析することで、ソースコード
レベルのブレークポイント設定・ステップ実行・変数参照を実現する。
GDB 相当の主要機能(ブレークポイント、ウォッチポイント、バックトレース、
マルチスレッド/マルチプロセス対応、式評価)をひとつのバイナリ内で
自己完結的に実装しており、外部デバッガライブラリ(libunwind 等)には
依存しない。

## 5. 前提・制約条件

- 動作環境は Linux / x86_64 に限定する(他 OS・他アーキテクチャは対象外)。
- デバッグ対象は ELF 実行ファイル(PIE / 非 PIE いずれも可)。共有ライブラリ
  単体や、ELF 以外の実行形式は対象外。
- デバッグ対象のソースコード表示・変数参照には DWARF デバッグ情報
  (`-g` 付きコンパイル)を要する。デバッグ情報が無い場合、対応する機能は
  逆アセンブル表示等へフォールバックするか、利用不可となる。
- ASLR は tdb がデバッグ対象プロセスに対して `personality(ADDR_NO_RANDOMIZE)`
  を設定することで無効化する。デバッグ対象自身が ASLR を要求する動作
  (セキュリティ検証目的等)は考慮しない。
- 表示メッセージは日本語・英語のみに対応する(`lang` コマンド)。

## 6. 機能要件

機能要件は以下のカテゴリに分類する。各要件 ID は
`REQ-<カテゴリ略号>-<連番>` とする。対応するコマンド・実装箇所は
[基本設計書](基本設計書.md) 6 章、詳細な処理手順は
[詳細処理手順書](詳細処理手順書.md) を参照。

### 6.1 実行制御 (EXEC)

| ID | 要件 | 対応コマンド |
| --- | --- | --- |
| REQ-EXEC-01 | 対象プログラムを起動し、`ptrace(2)` でトレース状態にできること。 | `run`/`r` |
| REQ-EXEC-02 | 実行を再開し、ブレークポイント/ウォッチポイント/シグナルまで進められること。 | `continue`/`c` |
| REQ-EXEC-03 | 機械語命令単位で1命令実行できること(`call` はステップイン)。 | `stepi`/`si` |
| REQ-EXEC-04 | 機械語命令単位で1命令実行し、`call` はまたいで実行できること。 | `nexti`/`ni` |
| REQ-EXEC-05 | ソース行単位でステップイン実行できること(DWARF 情報が必要)。 | `step`/`s` |
| REQ-EXEC-06 | ソース行単位でステップオーバー実行できること(DWARF 情報が必要)。 | `next`/`n` |
| REQ-EXEC-07 | 現在の関数の呼び出し元へ戻るまで実行を再開できること。 | `up` |
| REQ-EXEC-08 | 実行中のデバッグ対象プロセス(スレッドグループ全体)を終了できること。 | `kill`/`k` |
| REQ-EXEC-09 | tdb 自身が SIGINT (Ctrl-C) を受けた場合、自身は終了せずデバッグ対象へ SIGINT を転送し、通常のシグナル停止として扱えること。 | (実行制御全般で共通) |

### 6.2 ブレークポイント (BP)

| ID | 要件 | 対応コマンド |
| --- | --- | --- |
| REQ-BP-01 | 関数名を指定してブレークポイントを設定できること。 | `break <func>` |
| REQ-BP-02 | ファイル名:行番号を指定してブレークポイントを設定できること(DWARF 情報が必要)。 | `break <file>:<line>` |
| REQ-BP-03 | 16進アドレスを直接指定してブレークポイントを設定できること(プロセス起動後のみ)。 | `break *<addr>` |
| REQ-BP-04 | プロセス起動前でも関数名/ファイル:行番号指定を受け付け、`run` 時に解決すること。 | `break` (起動前) |
| REQ-BP-05 | `break <func>` はデバッグ情報の有無に関わらず、関数プロローグを通過した位置に設置すること。 | `break <func>` |
| REQ-BP-06 | 同一アドレスへの重複設置を拒否し、既存の番号を提示すること。 | `break` 全般 |
| REQ-BP-07 | 設定済みブレークポイントの一覧(番号・アドレス・関数名+オフセット・ソース位置・有効/無効)を表示できること。 | `info breakpoints`/`i b` |
| REQ-BP-08 | 番号を指定してブレークポイントを削除できること(ウォッチポイントと番号を共通管理)。 | `delete <n>`/`d` |
| REQ-BP-09 | `fork(2)`/`vfork(2)` で生成された子プロセスにも、既存および新規のブレークポイントが反映されること。 | (BP 全般、マルチプロセス時) |

### 6.3 ウォッチポイント (WP)

| ID | 要件 | 対応コマンド |
| --- | --- | --- |
| REQ-WP-01 | 変数名を指定して、その変数への書き込みを監視できること(DWARF 情報が必要)。 | `watch <var>` |
| REQ-WP-02 | アドレス式と監視幅(省略時8バイト)を指定して書き込みを監視できること。 | `watch *<addr式> [len]` |
| REQ-WP-03 | ハードウェアの制約上、最大4つまで同時設置できること。 | `watch` |
| REQ-WP-04 | 監視幅は 1/2/4/8 バイトのいずれかで、かつアドレスがそのバイト数境界に整列している必要があること(違反時はエラー)。 | `watch` |
| REQ-WP-05 | トリガー時に旧値・新値を表示できること。 | `watch` (トリガー時) |
| REQ-WP-06 | 設定済みウォッチポイントの一覧を表示できること。 | `info watchpoints`/`i w` |
| REQ-WP-07 | マルチスレッド対象では、既知の全スレッド・新規スレッドにも同じ監視設定を反映すること(ベストエフォート)。 | `watch` (マルチスレッド時) |

### 6.4 スレッド/マルチプロセス制御 (THR)

| ID | 要件 | 対応コマンド |
| --- | --- | --- |
| REQ-THR-01 | `clone(2)` (`pthread_create` 等) で生成されたスレッドを自動検出・追跡できること。 | (内部、`run` 後は自動) |
| REQ-THR-02 | 実行中のスレッド一覧(番号・tid・現在位置・フォーカス/ロック/プロセス種別の印)を表示できること。 | `info threads`/`i t` |
| REQ-THR-03 | フォーカス対象スレッドを番号指定で切り替えられること(停止中のスレッドのみ)。 | `thread <n>` |
| REQ-THR-04 | 既知の全スレッドへ順にフォーカスを切り替えながら指定コマンドを実行できること。 | `thread apply all <cmd>` |
| REQ-THR-05 | 指定スレッドのみ実行させ、他スレッドを停止させたままにできること(スケジューラロック相当)。 | `lock <n>` |
| REQ-THR-06 | ロックを解除し、保留中の他スレッドを再開できること。 | `unlock` |
| REQ-THR-07 | `fork(2)`/`vfork(2)` により生成された子プロセスを自動検出・追跡できること。 | (内部、`run` 後は自動) |
| REQ-THR-08 | 子プロセスが終了しても、他のプロセス/スレッドが残っていればセッションを継続できること。 | (内部) |

### 6.5 スタック/シンボル/ソース表示 (VIEW)

| ID | 要件 | 対応コマンド |
| --- | --- | --- |
| REQ-VIEW-01 | `rbp` チェインを辿ってコールスタックを表示できること(各フレームは関数名+オフセット、可能ならファイル:行番号を付記)。 | `backtrace`/`bt` |
| REQ-VIEW-02 | ELF シンボルテーブルの関数一覧を、任意の部分文字列で絞り込んで表示できること。 | `syms [filter]` |
| REQ-VIEW-03 | DWARF 行番号テーブルを、任意で関数名により絞り込んで表示できること。 | `lines [func]` |
| REQ-VIEW-04 | 現在位置/指定行/指定関数/指定アドレスを中心にソースコードを表示できること。 | `list`/`l` |
| REQ-VIEW-05 | ブレークポイント停止時・`step`/`next` 移動後は、該当行を中心に前後3行(計最大7行)を表示し、現在行に `>` マーカーを付けること。DWARF/ソースが無ければ1命令の逆アセンブルへフォールバックすること。 | (停止時共通表示) |
| REQ-VIEW-06 | 全レジスタ(汎用・rip・eflags・orig_rax・セグメント・fs_base/gs_base・x87・SSE・mxcsr)を表示できること。 | `info registers`/`i r` |

### 6.6 式評価 (print/set) (EXPR)

| ID | 要件 | 対応コマンド |
| --- | --- | --- |
| REQ-EXPR-01 | レジスタ参照 (`$rax` 等)、ローカル変数/仮引数、10進/16進整数リテラル、浮動小数点リテラルを評価できること。 | `print`/`set` |
| REQ-EXPR-02 | 四則演算・剰余・ビット演算 (`& | ^ ~ << >>`)・単項 `-`/`+`・括弧を評価できること。演算子優先順位・結合性は文法(`expr.y`)で定義すること。 | `print`/`set` |
| REQ-EXPR-03 | `&<変数名>` でローカル変数/仮引数の実体アドレスを取得できること。 | `print`/`set` |
| REQ-EXPR-04 | `*<addr式>` でメモリを8バイト整数として参照できること。 | `print`/`set` |
| REQ-EXPR-05 | `->`/`.` による構造体メンバアクセス、`[]` による配列/ポインタ添字アクセスに対応し、連鎖・混在できること。 | `print`/`set` |
| REQ-EXPR-06 | 式の文法エラーは自動修復せず、その場でエラーとして報告すること。 | `print`/`set` |
| REQ-EXPR-07 | `print <変数名>` 等、単一変数から始まる連鎖の結果が構造体/配列であれば整形表示できること。 | `print` |
| REQ-EXPR-08 | `print *<ポインタ変数>` は、型情報付きで指し示す先の値を表示できること。 | `print` |
| REQ-EXPR-09 | `print/x`,`o`,`t`,`d`,`i`,`c`,`s` で表示形式を明示指定できること。 | `print/<fmt>` |
| REQ-EXPR-10 | `set $<reg>=<式>` でレジスタに値を設定できること(st0-7/xmm0-15 含む)。 | `set` |
| REQ-EXPR-11 | `set <変数名>[…]=<式>` でローカル変数・構造体メンバ・配列要素に値を設定できること(型に応じた変換を含む)。 | `set` |
| REQ-EXPR-12 | `set *<addr式>=<式>` でメモリ1バイトを書き換えられること。 | `set` |
| REQ-EXPR-13 | `set print pretty on|off` で構造体/配列の複数行インデント表示を切り替えられること。 | `set print pretty` |
| REQ-EXPR-14 | `set print elements <n>|unlimited` で文字列/構造体・配列表示の要素数上限を設定できること。 | `set print elements` |
| REQ-EXPR-15 | 現在の `print` 設定を表示できること。 | `show print` |
| REQ-EXPR-16 | 現在の関数のローカル変数/仮引数、およびグローバル変数の一覧を表示できること。 | `show locals`/`show args`/`show globals` |
| REQ-EXPR-17 | 任意アドレス/レジスタから指定バイト数を16進ダンプ表示できること。 | `x/<n> <addr|$reg>` |

### 6.7 メモリリーク追跡 (LEAK)

| ID | 要件 | 対応コマンド |
| --- | --- | --- |
| REQ-LEAK-01 | `malloc`/`calloc`/`realloc`/`free` の呼び出しを捕捉し、有効/無効を切り替えられること。 | `leak on|off` |
| REQ-LEAK-02 | 現在の追跡状態(on/off・確保/解放回数・未解放件数)を表示できること。 | `leak` |
| REQ-LEAK-03 | 未解放のヒープ確保一覧を、確保元関数名・呼び出し位置(ファイル:行番号、無ければアドレス)付きで表示できること。 | `leaks` |
| REQ-LEAK-04 | 追跡対象アドレスは、実行ファイル自身のシンボルテーブル、無ければ libc の `.dynsym` から解決できること。 | (内部) |
| REQ-LEAK-05 | 追跡は `continue`(および内部で使う `up`/`nexti`)の実行区間でのみ有効であること。`stepi`/`step`/`next` は対象外でよい。 | (内部制約) |

## 7. 非機能要件

| 分類 | 要件 |
| --- | --- |
| 移植性 | Linux/x86_64 以外への移植は要件としない(明示的にスコープ外)。 |
| 保守性 | 表示文言は `locales/app.yml` に一元化し、コード側は `t!()` マクロ経由で参照すること(ハードコードした日本語/英語文字列を追加しない)。 |
| 保守性 | 式パーサーの文法は `src/expr.y`/`src/expr.l` に宣言的に記述し、`build.rs` でコード生成すること(手書きパーサーの追加拡張は行わない)。 |
| 信頼性 | 構文エラー時に自動修復(トークン挿入等)を行わず、即座にエラーとして報告すること(誤ったパニックを避けるため)。 |
| 応答性 | REPL の各コマンドはユーザー入力に対して同期的に応答すること(バックグラウンド処理は SIGINT 転送スレッドのみ)。 |
| セキュリティ | tdb 自身はデバッグ対象プロセスに対して `ptrace` 権限を要する。権限昇格・サンドボックス回避等の悪用目的の機能は要件としない。 |

## 8. スコープ外の機能

- Linux/x86_64 以外の OS・アーキテクチャへの対応。
- 共有ライブラリ(libc 等)自身のデバッグ情報を用いたシンボル解決・ソース表示(アドレス解決はメモリリーク追跡の内部処理のみで使用し、ユーザー向けのシンボル表示・逆アセンブルには使わない)。
- `-fomit-frame-pointer` でビルドされたバイナリでの `backtrace`/変数参照の正確な動作(rbp チェイン前提のため)。
- リモートデバッグ、コアダンプ解析、リバースデバッグ(逆方向実行)。
- GDB の全コマンド・全 `set print` オプションの網羅的な互換。
- 条件付きブレークポイント(`break ... if ...`)。
- `fork` 後の子プロセスによる `execve` の追跡(`PTRACE_EVENT_EXEC` は監視しない)。

## 9. 既知の制限事項

詳細は [README.md](../README.md) の「既知の制限」章および
[詳細処理手順書](詳細処理手順書.md) の各手順の注記を参照。主な項目を
以下に要約する。

1. `DW_AT_frame_base` が `DW_OP_call_frame_cfa` の場合、CFI を読まず
   `rbp+16` で近似するため、フレームポインタ省略ビルドやプロローグ実行前
   停止位置では変数値を正しく読めないことがある。
2. 共有ライブラリのシンボルは解決しない(バックトレースは `??` 表示)。
3. `*<addr式>` は「ポインタ型の裸の変数名」直後の場合を除き、常に8バイト
   読みの生アドレス演算になる。
4. マルチスレッド対応は GDB の all-stop 相当ではなく、フォーカス外の
   スレッドはバックグラウンドで動き続ける簡略実装。
5. `lock`/`unlock` はスレッド生成直後の極めて早いタイミングが重なると、
   稀に(概ね1%未満)対象スレッドの再開が `SIGSEGV` になることがある。
6. `fork` 後の子プロセスが別プログラムを `execve` した場合、追跡が
   正しく機能しなくなる。
7. `leak` の追跡は `continue` 系の実行区間限定であり、libc 内部の確保・
   解放も区別なく捕捉するためノイズが混ざることがある。
8. `nexti` の再帰時の戻り先ブレークポイントはフレーム識別をしないため、
   再帰呼び出し中に同じ戻りアドレスへ複数回ヒットしうる。

## 10. 動作確認環境

- OS: Linux (x86_64)
- コンパイラ: `rustc` (Rust 2021 edition)、デバッグ対象は `gcc -g -O0`
- 主要ライブラリ: `nix`, `goblin`, `gimli`, `iced-x86`, `rustyline`,
  `rust-i18n`, `cfgrammar`/`lrlex`/`lrpar` (grmtools)、詳細は
  [Cargo.toml](../Cargo.toml) を参照。
