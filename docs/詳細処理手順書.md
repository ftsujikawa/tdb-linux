# tdb 詳細処理手順書

本書は [基本設計書](基本設計書.md) で定義した各処理方式について、
`src/debugger.rs` を中心とした実装レベルの手順を記述する。各節の
「関連関数」はすべて `src/debugger.rs` 内(特記あるものを除く)。
行番号は 2026-07-27 時点のソースを基準とする(以後の改修で前後しうる)。

## 1. 起動処理

### 1.1 プロセス起動前(`main.rs` → `Debugger::new`)

1. `main()` が `LANG`/`LC_ALL` を読み、`en` で始まれば英語、それ以外は
   日本語を初期表示言語として `rust_i18n::set_locale` に設定する。
2. コマンドライン引数の先頭を対象プログラムパスとして取り出し、存在確認する。
3. `Debugger::new(program, args)` が ELF ファイルを読み込み、`ElfInfo`
   (シンボルテーブル)と `DwarfInfo`(`.debug_info`/`.debug_line`、
   存在しなければ空)を構築する。この時点ではプロセスはまだ起動しない。
4. `install_sigint_forwarder()` が SIGINT 監視用バックグラウンドスレッドを
   起動する(2.9 節参照)。
5. `repl::run_repl(dbg)` が REPL ループに入る。

### 1.2 `run` コマンド(`Debugger::start`)

1. 既に実行中なら `dbg.already_running` エラーで終了する。
2. `breakpoints`/`bp_ids`/`watchpoints`/`wp_ids`/`threads`/`thread_ids`/
   `pending_initial_stop`/`locked_tid`/`processes`/`leak`(`reset_for_run`)
   を初期化する(前回セッションの状態を引き継がない)。
3. `fork()` (Rust プロセスの `fork`、`nix::unistd::fork`) を呼ぶ。
   - 子プロセス側: `ptrace::traceme()` → `personality(ADDR_NO_RANDOMIZE)`
     で ASLR 無効化 → `execv(path, args)`。失敗時は `exit(127)`。
   - 親プロセス側(tdb 本体): `self.pid`/`self.current_tid` に子の pid を
     設定し、`DEBUGGEE_PID`(SIGINT 転送用のグローバル状態)を更新する。
4. 親は `waitpid(child, None)` で `execv` 直後の最初の `SIGTRAP` 停止を待つ。
5. `ptrace::setoptions` で `PTRACE_O_TRACECLONE | PTRACE_O_TRACEFORK |
   PTRACE_O_TRACEVFORK` を設定する。これにより以降の `clone(2)`/
   `fork(2)`/`vfork(2)` が自動的に ptrace アタッチされる。
6. メインスレッド(= `child`)を `threads`/`thread_ids`/`processes` へ
   直接登録する(`register_thread` は使わない。理由: メインスレッドの
   初回停止は手順4の `waitpid` で既に消化済みであり、`register_thread`
   経由だと `pending_initial_stop` に入って二重に読み飛ばそうとしてしまう)。
7. PIE バイナリなら `detect_load_bias()` で `/proc/<pid>/maps` から
   実行ファイル自身のマッピング開始アドレスを読み、`load_bias` に設定する
   (非 PIE なら 0)。
8. `pending_breaks`(起動前に指定された未解決のシンボル名/ファイル:行番号)
   を1つずつ `install_breakpoint_by_spec` で解決・設置する。個別の失敗は
   継続(他の保留ブレークポイントの設置を止めない)。
9. 起動完了メッセージ(pid・entry・PIE 有無)を表示する。

## 2. 実行制御

### 2.1 `step_over_current_breakpoint`(全実行制御の共通前処理)

`continue`/`stepi` は必ず先頭でこれを呼ぶ。現在の `rip` にちょうど
有効なブレークポイントが設置されている場合、そのまま `PTRACE_CONT`/
`PTRACE_SINGLESTEP` すると `int3` を再度踏むだけで前進しないため、
以下の手順で「1命令だけ実際の命令を実行してから元に戻す」処理を行う。

1. `rip` に有効なブレークポイントがなければ何もせず `Ok(None)` を返す。
2. ブレークポイントを `disable`(元のバイトへ書き戻す)。
3. `PTRACE_SINGLESTEP` で1命令実行し、`waitpid` で結果を待つ。
4. プロセス終了なら `mark_exited` して `Ok(None)` を返す。
5. `SIGTRAP` で停止した場合、`check_watchpoint_hit()`(3.3 節)で
   ハードウェアウォッチポイントの発火を確認する。発火していれば、
   ブレークポイントを再度 `enable` した上でメッセージを `Ok(Some(msg))`
   として返す(呼び出し元はこれを「ウォッチポイント停止」として報告し、
   本来予定していた `continue`/`step` は行わない)。
6. 発火していなければブレークポイントを再度 `enable` し、`Ok(None)` を返す。

この手順を怠ると、ブレークポイント直後の命令がちょうど監視対象への
書き込みだった場合にウォッチポイントの発火を見逃す不具合になる。

### 2.2 `continue`(`cont`)

1. `pid()`(= `current_tid`、未起動なら `dbg.not_running` エラー)を確認する。
2. `step_over_current_breakpoint()` を実行し、`Some(msg)` ならウォッチ
   ポイント停止として報告して終了する。
3. `self.exited` なら何もせず終了する(手順2の1命令実行で終了した場合)。
4. `leak.enabled` なら `ensure_leak_breakpoints_installed()`(6章)で
   `malloc`/`calloc`/`realloc`/`free` のフック用ブレークポイントを設置する。
5. `PTRACE_CONT` で `current_tid` を再開する。
6. `wait_and_report()`(2.4 節)で停止まで待ち、結果を報告する。
7. `leak.enabled` なら `uninstall_leak_breakpoints()` でフック用
   ブレークポイントを撤去する(ユーザーの実ブレークポイントと重複する
   ものは撤去しない)。

### 2.3 `stepi`/`nexti`

- `stepi`: 2.1 節の前処理の後、`self.exited` でなければ
  `PTRACE_SINGLESTEP` を1回実行し `wait_and_report()` で報告する。
- `nexti`: 現在の `rip` から16バイト読み、`call_instruction_len` で
  `call` 命令(`E8 rel32` および `FF /2`,`/3` の間接呼び出し)かを判定する。
  1. `call` でなければ `stepi()` と同じ処理にフォールバックする。
  2. `call` なら戻りアドレス(`rip + 命令長`)に一時ブレークポイントを
     設置する(既に同アドレスにブレークポイントがあれば新規設置しない)。
  3. `skip_target` に戻りアドレスを設定してから `cont()` を呼ぶ
     (メモリリーク追跡のフック処理が、このアドレスでの停止をユーザーに
     見せてよいかどうかの判定に `skip_target` を参照する)。
  4. `skip_target` を元の値に戻し、一時的に設置したブレークポイントで
     あれば `disable` して除去する。

### 2.4 `wait_and_report`(`continue` 系共通の停止処理ループ)

`waitpid(None, Some(WaitPidFlag::__WALL))` により、特定の tid ではなく
スレッドグループ内の任意のスレッド/プロセスのイベントを待つ(マルチ
スレッド/マルチプロセス対応の中核)。

1. **`PTRACE_EVENT_CLONE`**: `PTRACE_GETEVENTMSG` で新規 tid を取得し
   `register_thread()`(5.1 節)で登録、`resume_or_hold()` で再開判定して
   ループを継続する。
2. **`PTRACE_EVENT_FORK`/`PTRACE_EVENT_VFORK`**: 同様に新規 pid を取得し、
   `processes` にも追加した上で `register_thread()` を呼び、
   `resume_or_hold()` で再開判定してループを継続する。
3. **`Stopped(tid, _)`**(上記イベント以外の通常停止): まず
   `register_thread(tid)` を(未登録なら)呼ぶ(イベント通知の到達順序が
   前後した場合の保険)。
   - `pending_initial_stop` に含まれていれば(自動アタッチ直後の初回停止、
     `SIGTRAP`/`SIGSTOP` いずれもありうる)、無条件に読み飛ばして
     `resume_or_hold()` へ委ね、ループを継続する。
   - `locked_tid` が設定されており、かつ `tid` がロック対象でなければ、
     報告せず停止させたままループを継続する(手順4以降に進めない)。
4. 上記に該当しない停止を種別ごとに処理する。
   - **`Exited`/`Signaled`**: `on_thread_gone(tid)`(5.2 節)で後始末。
     既知の全プロセス/全スレッドが尽きていればセッション終了として
     報告して `return`、そうでなければ(かつそのスレッドがプロセス
     リーダーであれば)子プロセス終了メッセージを表示してループを継続する。
   - **`Stopped(tid, SIGTRAP)`**: `current_tid` をそのスレッドへ切り替える。
     1. `check_watchpoint_hit()` で発火していればウォッチポイント報告
        (`report_watchpoint`)をして `return`。
     2. `rip - 1` がブレークポイントアドレスなら、`rip` をそこへ補正して
        `set_regs`。
        - `leak.enabled` かつ `handle_leak_breakpoint(bp_addr)` が
          `true`(ユーザーに見せる必要のない内部フック)なら、
          `step_over_current_breakpoint()` を挟んでから `PTRACE_CONT` して
          ループを継続する(ユーザーには一切表示しない)。
        - それ以外はブレークポイント命中として `関数名+オフセット` 付きの
          メッセージを表示し、`show_stop_location`(2.5 節)で停止位置を
          表示して `return`。
     3. どちらでもなければ `dbg.stopped_sigtrap`(通常の `SIGTRAP`)として
        報告して `return`。
   - **`Stopped(tid, その他シグナル)`**: `current_tid` を切り替え、
     シグナル名を表示する。`SIGINT` の場合のみ追加でその場の停止位置
     (`show_stop_location`)も表示する(GDB の `continue` 中 Ctrl-C 相当の
     体験を再現するため。他のシグナルはシグナル名のみ)。`return`。

### 2.5 `show_stop_location` / `print_source_context`

1. `link_addr = addr - load_bias` を求め、`dwarf.lookup(link_addr)` で
   行情報を検索する。
2. 見つかれば `print_source_context(file, line)` を呼ぶ:
   - `CONTEXT = 3`。`start = max(1, line - 3)`、`end = line + 3` の範囲で
     ソースファイルを読み、該当行を `{}{:>4}\t{}` の形式(先頭列は現在行に
     `>`、それ以外は半角スペース)で出力する。ファイルが開けない/該当
     行が無ければ `false` を返す。
3. 行情報が無い、またはソースファイルが読めなければ、`read_mem_for_display`
   (ブレークポイントの `0xCC` を元のバイトへ戻した状態のメモリ)を16
   バイト読み、`iced-x86` (`disasm::disassemble_one`) で1命令だけ逆
   アセンブルして表示する。
4. `step`/`next` の移動後表示も同じ `print_source_context` を使う
   (2.6/2.7 節)。`list` コマンドは別関数 `show_source_window`
   (前後10行、マーカーなし)を使うため書式が異なる。

### 2.6 `step`(`step_line`)

1. 開始時点の `(file, line)` を記録する(`start_line`)。
2. ループ: `single_step_raw()`(2.1 節と同様にブレークポイント上での
   1命令実行を扱うが、`step_over_current_breakpoint` と異なり常に
   ちょうど1命令だけ進む)で1命令実行し、`classify_wait()` で分類する。
   - `Exited`/`Signaled`/`Unexpected`: 終了。
   - `Breakpoint(addr)`(ユーザー設置の実ブレークポイント): 命中
     メッセージと `show_stop_location` を表示して終了。
   - `Watchpoint(msg)`: メッセージと `show_stop_location` を表示して終了。
   - `Other(rip)`(一時ブレークポイント/ブレークポイントでない通常停止):
     - `dwarf.lookup(link_ip)` が `is_stmt` かつ `start_line` と異なる
       行を指せば、`print_source_context` (失敗時はファイル:行のみ) を
       表示して終了。
     - 行番号情報はあるが同じ行/`is_stmt` でなければループを継続
       (同じ行内の複数命令をスキップ)。
     - 行番号情報が無ければ(共有ライブラリ等デバッグ情報の無いコードへ
       `call` で入った場合)`finish_undebugged_frame()`(2.8 節)で
       戻りアドレスまで一気に実行し、ループを継続する。

`call` 命令もそのまま1命令として `single_step_raw` されるだけなので、
呼び出し先に自然にステップインする。

### 2.7 `next`(`next_line`)

`step_line` とほぼ同じループ構造だが、命令列を見て `call` 命令に
差しかかったことを検出した場合、呼び出し先には入らず
`call_instruction_len` で求めた戻りアドレスに一時ブレークポイントを
置いて `continue` することでまるごと実行してから、行単位のステップを
続ける(`nexti` と同じ戻りアドレス算出ロジックを利用)。呼び出し先の中で
ユーザー設置の実ブレークポイントに当たった場合はそこで停止する。

### 2.8 `finish_undebugged_frame`

`step`/`next` がデバッグ情報の無い関数(共有ライブラリ等)に入った際に
使う内部処理。

1. `[rsp]` から戻りアドレスを読む。
2. そのアドレスに(まだ無ければ)一時ブレークポイントを設置する。
3. `PTRACE_CONT` して `waitpid` で待つ(`wait_and_report` は使わず、
   単一スレッド向けの素朴な `waitpid` で待つ点に注意。これがマルチ
   スレッド対応の「既知の制限」の一因になっている)。
4. 終了/シグナル終了ならそのまま報告。`SIGTRAP` で一時ブレークポイントに
   命中していれば `rip` を補正する。
5. 一時的に設置したブレークポイントであれば取り除く。

### 2.9 SIGINT 転送

1. `main()` から `install_sigint_forwarder()` を一度だけ呼ぶ。
2. `signal_hook::iterator::Signals::new([SIGINT])` でシグナル監視イテレータ
   を作り、専用スレッドで `for _ in signals.forever()` ループする。
3. SIGINT を受けるたびに `DEBUGGEE_PID`(`AtomicI32`、実行中のデバッグ対象
   pid、無ければ0)を読み、0より大きければその pid へ `SIGINT` を送る。
4. これにより tdb 自身は SIGINT のデフォルト動作(終了)をせずに動き
   続け、デバッグ対象は ptrace 経由でシグナル停止として捕捉され、
   `wait_and_report` の「`Stopped(tid, その他シグナル)`」経路で通常の
   シグナル停止として報告される(2.4 節手順4参照)。

## 3. ブレークポイント/ウォッチポイント

### 3.1 `break` コマンド(`break_at_spec`)

1. 先頭が `*` なら16進アドレスとして `parse_addr` し、`install_breakpoint`
   へ直接進む(起動前は使用不可。`self.is_running()` を要求しないため
   実際には未起動時にも呼べてしまうが、後続のレジスタ操作等は失敗する
   前提の簡易実装)。
2. 未起動なら `pending_breaks` に文字列のまま積んで保留する
   (`dbg.pending_break_deferred` を表示)。
3. 起動済みなら `install_breakpoint_by_spec` へ進む:
   - コロンを含み、コロン右側が数値としてパース可能なら
     `install_breakpoint_by_location`(ファイル:行番号)。
   - そうでなければ `install_breakpoint_by_name`(関数名)。

**関数名解決 (`install_breakpoint_by_name`)**
1. `elf.find_by_name(name)` でシンボルを引く(無ければエラー)。
2. `runtime_addr(sym.addr)` でエントリアドレスを実行時アドレスへ変換。
3. `skip_prologue_addr(sym, entry_addr)` でプロローグ通過位置を求める
   (下記)。
4. `install_breakpoint(addr, name)` で設置。

**プロローグ判定 (`skip_prologue_addr`)**
1. シンボルのアドレス範囲 `[low, high)` を求める(`size` が0の場合は
   次に小さいシンボルアドレスまでを範囲とみなし、それも無ければ
   `low + 0x1000` を仮の上限とする)。
2. `dwarf.skip_prologue(low, high)` が値を返せば(DWARF 行テーブル上で
   行番号が変化する最初のアドレス)それを実行時アドレスへ変換して使う。
3. DWARF が無ければ、エントリアドレスから32バイト読み、
   `disasm::skip_prologue_heuristic` で `endbr64`/`push rbp`/
   `mov rbp,rsp`/`sub rsp,N` という典型的な命令列を `iced-x86` で
   デコードして判定する。パターンに一致しなければ関数先頭のままとする。

**ファイル:行番号解決 (`install_breakpoint_by_location` → `resolve_file_line`)**
1. `file_part` に一致する行(フルパス・ファイル名・パス末尾一致の
   いずれか)を DWARF 行テーブルから絞り込む(`end_sequence` は除外し
   `is_stmt` のみ対象)。
2. `(line, addr)` で昇順ソートし、`line >= 指定行` を満たす最小の行を採用
   する(指定行そのものに実行可能なコードが無い場合のフォールバック)。
3. 該当が無ければエラー。

**重複防止 (`install_breakpoint`)**
1. `breakpoints` に同一アドレスが既にあれば、`bp_ids` から対応する
   番号を検索してエラーメッセージに含め、設置を拒否する。
2. 新しい通し番号を発行し `bp_ids` に登録、`Breakpoint::new(addr)` を作る。
3. 実行中なら `current_tid` に対して `enable`(`int3` パッチ)する。
4. `processes` に他のプロセスリーダー(`fork` 由来の子)があれば、
   `install_in` でベストエフォート反映する(失敗は無視)。
5. `breakpoints` マップへ登録し、設置完了メッセージを表示する。

### 3.2 `info breakpoints`(`list_breakpoints`)

1. `bp_ids` を番号昇順で走査する。
2. 各アドレスについて `elf.find_by_addr(link_addr)` でシンボルを引き、
   アドレスがシンボル先頭と一致すれば `<関数名>`、一致しなければ
   `<関数名+オフセット>`(16進)の形式にする。シンボルが無ければ `<?>`。
3. `dwarf.lookup(link_addr)` があれば ` at ファイル:行番号` を付記する。
4. `breakpoints` の `enabled` が `false` なら無効である旨の注記を付ける。

### 3.3 `watch` コマンド(`add_watchpoint`)

1. 監視幅 `len` が `{1,2,4,8}` のいずれでもなければエラー。
2. `addr % len != 0`(アライメント違反)ならエラー。
3. `watchpoints` の空きスロット(DR0-DR3 のいずれか)を探す(無ければ
   `dbg.watch_max` エラー、最大4つ)。
4. 現在値を読み `last_value` として保持する。
5. `install_watch_slot(current_tid, slot, addr, len)` で DR`slot` に
   アドレスを、DR7 で書き込み監視・幅・ローカル有効化ビットを設定する
   (`dr7_len_bits`: 1→`00`, 2→`01`, 8→`10`, 4→`11`)。
6. 他の既知スレッドにも同じ設定をベストエフォートで反映する(失敗は無視。
   バックグラウンドで動作中のスレッドは DR レジスタを読み書きできない
   ことがあるため)。
7. 通し番号を発行し `wp_ids`/`watchpoints[slot]` に登録する。

**発火検出 (`check_watchpoint_hit`)** — `SIGTRAP` 受信のたびに呼ばれる。
1. DR6 を読み、下位4ビットがすべて0なら発火なし(`None`)。
2. 立っているビットごとに対応するスロットのウォッチポイントを特定し、
   現在値を読んで `last_value` と比較、`旧値`/`新値` 付きメッセージを
   組み立てる。
3. `last_value` を新しい値で更新する。
4. 最後に DR6 を0にクリアする(古いステータスが次回の判定に残らない
   ようにするため)。

この関数は `step_over_current_breakpoint`・`wait_and_report`・
`classify_wait`(`step`/`next` 経路)の3箇所すべてから呼ばれ、
ブレークポイント踏み越え中の1命令実行でもウォッチポイント発火を
見逃さないようにしている。

### 3.4 `delete` コマンド

1. `wp_ids` に該当番号があればウォッチポイント削除(`delete_watchpoint`):
   スロットを `None` にし、既知の全スレッドから `uninstall_watch_slot`
   (ベストエフォート)する。
2. なければブレークポイント削除(`delete_breakpoint`): `bp_ids` から
   除去し、実行中かつ未終了なら `current_tid` で `disable`、他の
   プロセスリーダーからも `remove_from` する。

## 4. スタック/シンボル表示

### 4.1 `backtrace`

1. `current_tid` のレジスタから `rip`/`rbp` を取得する。
2. 深さ0から最大64フレームまでループ:
   - `link_ip = rip - load_bias` で `elf.find_by_addr` を引き、
     `link_ip` がシンボル先頭と一致すれば `関数名`、一致しなければ
     `関数名+オフセット` を組み立てる。
   - `dwarf.lookup(link_ip)` があれば `ファイル:行番号` を付記して
     `#depth addr in sym at file:line` を出力、無ければ `#depth addr in sym`。
   - `rbp == 0` なら終了。
   - `[rbp]`(保存された旧 `rbp`)と `[rbp+8]`(戻りアドレス)を読む。
   - 戻りアドレスまたは保存 `rbp` が0なら終了。
   - `rip = 戻りアドレス`、`rbp = 保存された旧rbp` として次のフレームへ。

`-fomit-frame-pointer` ビルドや関数プロローグ実行前の停止位置では
`rbp` チェインの前提が崩れるため、正しく辿れないことがある(README
「既知の制限」参照)。

### 4.2 `syms`/`lines`/`list`

- `syms [filter]`: `elf.symbols` を(`filter` があれば部分一致で
  絞り込んで)そのまま表示する。実行中はロードバイアス加算後、
  未実行ならリンク時アドレスのまま表示する。
- `lines [func]`: `dwarf` の行テーブルをアドレス昇順で表示する。
  `func` があれば `elf.find_by_name` でアドレス範囲を求め、その範囲内の
  行だけに絞り込む。`end_sequence` の行は表示しない。
- `list`: `list_source` がオペランドを判別する。
  1. `*<addr>` → `location_from_address`(実行中/未実行でランタイム/
     リンク時アドレスを切替、`.debug_line` から行を逆引き)。
  2. 数値のみ → `current_source_location` のファイルでその行番号。
  3. `<file>:<line>` → `resolve_source_file` で照合したファイルのその行。
  4. それ以外 → `location_from_function`(`elf.find_by_name` → DWARF 行)。
  5. オペランド省略 → 実行中ならその時点の PC の行、未実行なら `main`
     関数の先頭行。
  最後に `show_source_window(file, line)` が `WINDOW = 10` 行を
  (マーカーなしで)表示する。

## 5. スレッド/マルチプロセス管理

### 5.1 スレッド登録 (`register_thread`)

`PTRACE_EVENT_CLONE` 検出時、`wait_and_report` から呼ぶ。
1. `threads.insert(tid)` が真(未登録だった)なら、新しい表示用番号を
   発行して `thread_ids` に登録する。
2. `pending_initial_stop.insert(tid)`(次に来る初回停止を無条件で
   読み飛ばすためのマーク。カーネル/タイミングにより `SIGTRAP` のことも
   `SIGSTOP` のこともあり、シグナル種別では判別しない)。
3. 既存の全ウォッチポイントスロットについて、`install_watch_slot(tid,
   slot, addr, len)` をベストエフォートで反映する(新規スレッドでも
   同じ監視を維持するため)。

### 5.2 スレッド終了時の後始末 (`on_thread_gone`)

1. `threads`/`thread_ids`/`processes` から `tid` を除去する。
2. `current_tid == tid` なら、残っている別のスレッドへフォールバック
   (無ければ `None`)。
3. `locked_tid == tid`(ロック対象自身が終了)なら、ロックを解除し、
   停止させたままにしていた他の全スレッドを `release_held_thread` で
   再開する(ロックしたまま全スレッドが止まったままになるのを防ぐ)。

### 5.3 `thread <n>`(`switch_thread`)

1. `resolve_thread_id(id)`(表示用番号優先、無ければ生の OS tid として
   解釈)で tid を解決する。
2. `locked_tid` が設定されており、かつロック対象と異なれば
   `dbg.thread_locked_cannot_switch` エラー。
3. `fixup_breakpoint_rip(tid)`(レジスタが読めるか = ptrace 停止中かを
   確認し、ブレークポイント直後の rip 補正も行う)に失敗すれば
   `dbg.thread_not_stopped` エラー(バックグラウンド動作中のスレッドへは
   切り替えられない)。
4. `current_tid` を更新し、切り替えメッセージと `show_stop_location`
   を表示する。

### 5.4 `lock <n>` / `unlock`

**`lock_thread`**
1. tid を解決し、`fixup_breakpoint_rip` でレジスタを読めることを確認する
   (失敗ならエラー)。
2. `locked_tid`/`current_tid` を対象へ設定する。
3. 他の既知スレッドのうち、`/proc/<tid>/status` の `State:` が
   `R`/`S`/`D`(実行中)であるものへ `SIGSTOP` を送る(既に停止中の
   ものには送らない)。
4. ロックメッセージと停止位置を表示する。

**`unlock_thread`**
1. `locked_tid` を `None` に戻す(以前ロックされていなければ
   `dbg.thread_not_locked` を表示するのみ)。
2. `current_tid` 以外の全既知スレッドを `release_held_thread` で再開する。

**`release_held_thread`(`lock`/`unlock` 双方から使う共通処理)**
1. 対象スレッドのレジスタを読む(失敗時は何もしない)。
2. `rip - 1` が有効なブレークポイントアドレスであれば(= `int3`
   実行直後で保留されていた場合)、`rip` をそこへ補正 → ブレークポイント
   を一時 `disable` → `PTRACE_SINGLESTEP` で1命令だけ踏み越え →
   `waitpid` → 再度 `enable`、という手順を踏んでから `PTRACE_CONT` する
   (素朴に `PTRACE_CONT` すると命令境界がずれ `SIGSEGV` になるため)。
3. ブレークポイント直後でなければそのまま `PTRACE_CONT` する。

**`resume_or_hold`(`wait_and_report` 内部で使用)**: `locked_tid` が
未設定、またはロック対象自身であれば `PTRACE_CONT` する。ロック中で
ロック対象以外であれば何もしない(停止させたまま)。

### 5.5 `thread apply all <cmd>`(`repl.rs::thread_apply_all`)

1. `thread_ids_sorted()` で既知の全番号(`fork` 由来の別プロセスの
   スレッドも含む)を昇順取得する。
2. `current_focus()` で現在のフォーカスを保存する。
3. 番号ごとに `focus_thread_for_apply(id)`(`lock` 中でも対象を問わず
   一時的にフォーカスできる内部専用経路。停止していなければスキップして
   次へ)でフォーカスを切り替え、`dispatch(dbg, sub_cmd)` を再帰的に
   実行する。
4. 全番号を処理したら `restore_focus(saved)` で元のフォーカスへ戻す。
   `sub_cmd` が `quit` 等で REPL 終了を要求した場合はフォーカス復元を
   行わずに `false` を返す。

### 5.6 `fork(2)`/`vfork(2)` の自動追跡

1. `run` 時点で設定した `PTRACE_O_TRACEFORK`/`PTRACE_O_TRACEVFORK`
   により、`wait_and_report` が `PTRACE_EVENT_FORK`/`PTRACE_EVENT_VFORK`
   を検出する(2.4 節手順1参照)。
2. `PTRACE_GETEVENTMSG` で新規 pid を取得し、`processes.insert(new_pid)`
   に加え `register_thread(new_pid)`(スレッドと同じ登録経路を流用し、
   `info threads` の番号付けとウォッチポイント反映を共有する)。
3. `info threads` の表示では、`Some(tid) != self.pid &&
   self.processes.contains(&tid)` を満たすものに `[プロセス]` の印を
   付ける(メインプロセス自身とは区別する)。
4. ブレークポイントは `fork` 時点でメモリごとコピーされるため、
   既存のものは追加作業なしに子プロセスでも有効。`fork` 後に新規設置
   した場合のみ `processes` の全プロセスへ `install_in` で反映する
   (3.1 節手順4)。
5. `PTRACE_EVENT_EXEC` は監視していないため、子プロセスが `fork` 後に
   別プログラムを `execve` した場合、アドレス空間が丸ごと入れ替わり
   追跡が正しく機能しなくなる(既知の制限)。

## 6. メモリリーク追跡

### 6.1 フック設置 (`ensure_leak_breakpoints_installed`、`continue` 冒頭で呼ぶ)

1. `leak.entries` が空なら `resolve_leak_entry_points()`(下記)を試みる。
2. それでも空、かつ `warmed_up` が `false` なら:
   - `find_libc_mapping()` が `None`(libc 未マップ)を返せば
     `warm_up_to_own_entry()` を実行する。これは実行ファイル自身の
     エントリポイント(`_start`)へ一時ブレークポイントを置いて
     `continue`+生 `waitpid` で内部的に(ユーザーに見えない形で)進める
     処理(`finish_undebugged_frame` と同型のパターン)。ld.so は
     依存する共有ライブラリ(libc 含む)をすべて読み込んでから実行
     ファイル自身のエントリへ制御を渡すため、到達すれば libc は必ず
     マップ済みになる。
   - 完了後、`resolve_leak_entry_points()` を再試行する。
   - `warmed_up` はプロセス実行につき1回だけ試みるフラグ(失敗しても
     無限に再試行しない)。
3. `leak.entries` の各アドレスについて、`breakpoints` に未登録なら
   `Breakpoint::new(addr)` を `current_tid` で `enable` し登録する。

**`resolve_leak_entry_points`**
1. `malloc`/`calloc`/`realloc`/`free` について、まず自プログラムの
   `elf.find_by_name` を試す(静的リンクバイナリならここで解決する)。
2. 解決できなかった分だけ `find_libc_mapping()` で `/proc/pid/maps`
   から libc のロードアドレスとパスを求め、libc 自身の `.dynsym`
   (`load_dynamic_symbols`)からアドレスを解決する。
3. 結果を `leak.entries`(実行時アドレス→`AllocFn`)に格納する。

### 6.2 呼び出し捕捉 (`handle_leak_breakpoint`、`wait_and_report` から呼ぶ)

1. ヒットしたアドレスが `leak.entries` にあれば `on_alloc_entry(func)`
   を呼ぶ。ユーザーの実ブレークポイントと重複していなければ `true`
   (= 静かに再開してよい)を返す。
2. ヒットしたアドレスが `leak.pending`(戻りアドレス捕捉待ち)にあれば
   `on_alloc_return(addr)` を呼ぶ。ユーザーの実ブレークポイント、または
   `skip_target`(`nexti`/`up` が待っている一時停止先)と重複していなければ
   `true` を返す。
3. どちらでもなければ `false`(リーク追跡とは無関係の停止)。

**`on_alloc_entry`**
- `free`: `rdi`(引数のポインタ)を読み、`leak.live` から即座に削除する
  (`total_frees` 加算)。見つからなければ `bad_frees` に記録する。
- `malloc`/`calloc`/`realloc`: `[rsp]` から戻りアドレスを読み、サイズ
  (`malloc`=`rdi`、`calloc`=`rdi*rsi`、`realloc`=`rsi`)と旧ポインタ
  (`realloc` のみ `rdi`)を控える。戻りアドレスに一時ブレークポイントを
  設置し、`leak.pending` に `PendingCall` として積む。

**`on_alloc_return`**
- `leak.pending` から取り出し、`rax`(確保されたポインタ)が非0なら
  `leak.live` に `LiveAlloc { size, func, call_site }` として登録する
  (`realloc` で旧ポインタが確保元と異なる場合も含め、詳細は実装参照)。

### 6.3 フック撤去 (`uninstall_leak_breakpoints`、`continue` の最後で呼ぶ)

1. `leak.entries`/`leak.pending` の各アドレスについて、ユーザーの実
   ブレークポイント(`bp_ids` に含まれる)と重複していなければ
   `breakpoints` から除去し `disable` する。
2. `leak.pending` をクリアする(戻り値捕捉待ちの状態は `continue` の
   実行区間をまたいで持ち越さない)。

### 6.4 `leaks` 表示

1. `leak.enabled` でなければ無効である旨のみ表示する。
2. `leak.live` をアドレス昇順で列挙し、各エントリについて
   `dwarf.lookup(call_site)` があれば `ファイル:行番号`、無ければ
   戻りアドレスの16進表示を「確保元」として付記する。
3. `bad_frees`(追跡外への free)があれば別途件数と一覧を表示する。

## 7. 式評価 (`print`/`set`/`watch`/`x`)

### 7.1 パース

1. `repl.rs` がコマンド引数を1つの文字列に結合する。
2. `expr::eval`/`expr::eval_typed` が `expr.l`(lrlex 生成レキサー)+
   `expr.y`(lrpar 生成パーサー、LALR)でトークン化・構文解析し、
   `RawExpr`(構文木)を得る。
3. 構文エラーは `RecoveryKind::None`(`build.rs` で設定)により自動修復
   されず、その場で `Result::Err` として返る。

演算子優先順位(`expr.y` の `%left`/`%right` 宣言、上に書いたものほど
優先度が低い): `|` → `^` → `&` → `<<`/`>>` → `+`/`-` → `*`/`/`/`%` →
単項(`UMINUS` 疑似トークンへの `%prec` 指定で単項 `-`/`+`/`~`/`*`
(デリファレンス)/`&`(アドレス取得)の優先順位を分離)。

### 7.2 評価 (`eval_ast`)

`RawExpr` を再帰的に辿り、`Debugger` への参照を使って実際の値を求める。

- `Ident(name)`: `resolve_variable(name)`(7.3 節)でアドレスを求め、型に
  応じて読み出す。
- `Num`/`Float`: リテラルをそのまま `Value::Int`/`Value::Float` にする。
- `Reg(name)`: `registers::get_by_name`(st0-7/xmm0-15 は下位64bit)。
- `Unary(op, e)`: `-`/`+`/`~` を整数/浮動小数点に応じて適用する(ビット
  演算は整数のみ)。
- `Binary(op, l, r)`: どちらかが浮動小数点なら両方を `f64` に昇格して
  演算する。ビット演算・剰余は整数のみ対応。
- `Deref(e)`: `e` を評価してアドレスとし、8バイト読み(型情報を持たない
  生アドレス演算、常に整数)。
- `AddrOf(name)`: `name` は裸の識別子でなければならない(文法上
  `'&' IDENT` としてのみ許可)。`resolve_variable` のアドレスをそのまま
  返す。
- `Chain(base, steps)`: 7.4 節。

`print`/`set` レベルでの `*`/`&` の二項/単項判別は文法規則で解決済み
(`Expr '*' Expr` と `'*' Expr %prec UMINUS` を別規則として書き分け)
であり、評価時点では既に構文木として確定している。

### 7.3 変数解決 (`resolve_variable`)

1. `current_tid` のレジスタから `rip` を取得し、`link_pc = rip - load_bias`
   を求める。
2. `dwarf.find_variable(link_pc, name)` で、現在の PC を含む関数
   (`DW_TAG_subprogram`)のスコープ内(`DW_TAG_lexical_block` を含む)を
   名前で検索し、`(SubprogramInfo, VarInfo)` を得る。
3. `eval_frame_base(sub.frame_base, regs)`:
   - `DW_OP_call_frame_cfa`(オペコード `0x9c`)なら CFI を読まず
     `rbp + 16` で近似する。
   - `DW_OP_bregN`(`0x70`-`0x8f`)なら SLEB128 オフセットを読み、対応する
     DWARF レジスタ番号(x86-64 System V ABI: 0=rax,1=rdx,2=rcx,3=rbx,
     4=rsi,5=rdi,6=rbp,7=rsp,8-15=r8-r15 等)の値にオフセットを加える。
4. `eval_location(var.location, frame_base, regs)`:
   - `DW_OP_fbreg`(`0x91`): フレームベース + SLEB128 オフセット。
   - `DW_OP_addr`(`0x03`): 後続8バイトのリンク時絶対アドレスを
     `runtime_addr` で実行時アドレスへ変換(グローバル変数用)。
   - `DW_OP_bregN`(`0x70`-`0x8f`): レジスタ値 + SLEB128 オフセット。
   - 上記以外のオペコードは未対応としてエラー(ロケーションリスト等)。

### 7.4 連鎖アクセス (`->`/`.`/`[]`)

1. 連鎖の先頭 (`Chain` の `base`)は裸の識別子でなければならない
   (`resolve_variable` で解決できる必要があるため)。
2. `resolve_chain_steps`(`expr.rs`)が `RawChainStep` を `ChainStep`
   (`Field(name)`/`Index(expr)`)へ変換する。`Index` の中身は完全な式
   として再帰的に評価する(`arr[i+1]` 等も可)。
3. 各ステップを順に適用する:
   - `Field`: 現在の型がポインタなら1回だけ暗黙にデリファレンスして
     から、構造体/共用体としてメンバを `DW_TAG_member` の `offset` で
     探す(`->`/`.` を意味的に区別しない)。
   - `Index`: 配列ならそのアドレス、ポインタなら格納されている値を
     ベースアドレスとし、要素の型サイズでストライドする。
4. 型の再帰解決は無限再帰防止のため16段で打ち切る(連結リスト等、
   構造体がポインタ経由で自身を含む場合の対策)。
5. 連鎖の最終ステップの型が整数/浮動小数点/ポインタなら値として
   読み書きでき、構造体/配列なら 7.5 節の整形表示の対象になる。

### 7.5 整形表示 (`format_value_by_type`/`format_struct_value`)

1. `print <変数名>` またはそれに続く `->`/`.`/`[]` 連鎖だけで構成される
   式で、最終結果が構造体/配列型であれば整形表示する。
2. 構造体: `{a = 1, b = 2}`(メンバごとに `format_value_by_type` を
   再帰呼び出し)。配列: `{1, 2, 3}`(要素ごとに同様)。要素数は
   `print_elements`(既定200、`unlimited` で無制限)で打ち切る。
3. ポインタ型メンバ/要素は指す先を辿らずアドレスの16進表示のみ行う。
4. `print_pretty` が有効な場合は複数行インデント表示になり、値の直前に
   `(型名)` を付記する(`format_value_by_type` が `depth` に応じて
   インデント幅を制御する)。
5. `print *<ポインタ変数>` は特別扱い(`read_deref_for_print`): `<変数名>`
   がポインタ型のローカル変数/仮引数の場合に限り、DWARF の pointee 型を
   使って指し示す先を型情報付きで読む。それ以外の `*` の使い方
   (`*(p)`・`*&x`・`*p->next` 等)は 7.2 節の `Deref` と同じ、型情報を
   持たない8バイト読みのままとなる。

### 7.6 `set` の代入処理

`repl.rs::handle_set` が代入先を以下の優先順位で判定する。
1. `*` プレフィックス → `write_mem(addr, [value as u8])`(1バイト単位、
   コードパッチ用途を想定)。
2. `$` プレフィックス → `set_reg(name, value)`(レジスタ。st0-7/xmm0-15
   を含む。7.7 節)。
3. `->`/`.`/`[]` を含む → `parse_pure_chain` で連鎖を解析し
   `write_member_chain(base, steps, value)`。
4. それ以外 → `write_variable(name, value)`(ローカル変数/仮引数)。

`write_variable`/`write_member_chain` は対象の DWARF 型サイズ
(`DW_AT_byte_size`、最大8バイト)ぶんだけ書き込む。型が `DW_ATE_float`
(浮動小数点)なら値を IEEE754 ビット列(4バイトなら `f32`、それ以外は
`f64`)へ変換して書き込み、整数値が渡された場合も自動的に浮動小数点へ
変換する。型が浮動小数点でなければ、渡された値が浮動小数点なら整数へ
切り捨てる(C の暗黙変換相当)。

### 7.7 レジスタ設定 (`set_reg`)

- `st0`-`st7`: 式の評価値を `f64` として解釈し、
  `registers::encode_x87_extended` で80bit拡張精度へ変換して該当
  レジスタのバイト列を書き換え、`PTRACE_SETFPREGS` 相当の
  `setregset::<NT_PRFPREG>` で反映する。
- `xmm0`-`xmm15`: 式の評価値を整数として解釈し、下位64bitへ書き込み
  上位64bitは0にする(`movq xmm, r64` と同じ zero-extend)。
- それ以外の汎用レジスタ: `registers::set_by_name` で該当フィールドを
  直接書き換え、`PTRACE_SETREGS` で反映する。

## 8. レジスタ/メモリ表示

### 8.1 `info registers`

`PTRACE_GETREGS`(汎用レジスタ・rip・eflags・orig_rax・セグメント・
fs_base/gs_base)と `PTRACE_GETFPREGS`
(`nix::sys::ptrace::getregset::<NT_PRFPREG>`、x87 st0-7・SSE xmm0-15・
mxcsr)を取得し、`registers::dump`/`dump_fpregs` で整形する。`st`
レジスタは10バイトの生バイト列と、そこから変換したおおよその `f64` 値の
両方を表示する(簡易変換、非正規化数/NaN/無限大の厳密な扱いはしない)。
`xmm` レジスタは上位/下位64bitに分けた生の16進値として表示する。

### 8.2 `x/<n> <addr|$reg>`

1. `count` をコマンド名(`x/16` 等)または直後の `/16` トークンから取得
   (省略時16)。
2. アドレス引数が `$reg` ならレジスタ値を、`0x...` なら16進数値として
   解釈する。
3. `read_mem(addr, count)` で読み、8バイトずつ改行して16進ダンプする。

## 9. 多言語対応

1. `locales/app.yml` に `ja`/`en` の訳文を1ファイル(`_version: 2`)で
   管理する。
2. コードは `t!("キー", 名前 = 値, ...)` マクロで参照する。`%{名前}`
   プレースホルダは値に置換され、`t!(..., 値 : {:#x})` のように書式
   指定子を添えられる。
3. `lang <en|ja>` コマンドは `rust_i18n::set_locale` を呼ぶだけで、
   以降の全 `t!()` 呼び出しに即座に反映される(状態を跨いだ再読み込みは
   不要)。
4. 識別子(関数名・変数名・レジスタ名等、ユーザー入力/DWARF情報由来の
   文字列)やコマンド構文自体(`on`/`off` 等)は翻訳キーに含めず、
   `%{名前}` へそのまま渡すことで両言語共通表示にする。

## 10. `kill`/終了処理

1. 実行中(`pid` が `Some` かつ `!exited`)なら、既知の全スレッド
   (`threads`)へ `SIGKILL` を送り(`PTRACE_KILL` は非推奨のため未使用)、
   さらにメインプロセスへも念のため `SIGKILL` を送る。
2. ptrace 停止中のスレッドは `SIGKILL` を受けても `PTRACE_CONT` 等で
   再開されるまで終了処理が遅延することがあるため、全スレッドへ
   `PTRACE_CONT` を送って確実に処理させる。
3. `waitpid(None, __WALL)` を最大64回ループして既知の全スレッドの終了を
   刈り取る(無限ブロックを避けるための上限付き)。
4. `mark_exited()` に加え `pid`/`current_tid`/`threads`/`thread_ids`/
   `pending_initial_stop`/`locked_tid`/`processes` をすべてクリアする。
5. `quit`/`exit` コマンドは、実行中であればこの `kill()` を先に呼んで
   から REPL ループを終了する。
